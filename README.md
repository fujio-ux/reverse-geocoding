# reverse-geocoding — GPS の緯度経度から一番近い町字（オフライン、ESP32 向け）

GPS で取った緯度経度から、**一番近い町字の代表点**を探し、「都道府県・市区町村・大字・町（小字）・丁目」を出すためのデータと検索コード。
ネットにつながらない ESP32 で使えるよう、軽い 1 ファイル（RGEO 形式）にしてある。

例：`35.690395, 139.7661275` → 東京都千代田区内神田一丁目（代表点まで 52 m）

## 元データ

デジタル庁「アドレス・ベース・レジストリ」（https://dataset.address-br.digital.go.jp/ 、**CC BY 4.0**）

| ファイル | 中身 | 入手先 |
|---|---|---|
| 町字マスター（全国） | 町字の名前（都道府県・郡・市・区・大字・町・丁目・小字） | `https://data.address-br.digital.go.jp/mt_town/mt_town_all.csv.zip` |
| 町字マスター位置参照拡張（都道府県ごと 47 個） | 町字の代表点の緯度経度 | `https://data.address-br.digital.go.jp/mt_town_pos/pref/mt_town_pos_prefXX.csv.zip` |

- 町字マスターには緯度経度が無く（2026 年の形式）、位置参照拡張と `lg_code`＋`machiaza_id` でつなぐ。全国版の位置参照拡張は無い（404）ので都道府県ごとに取る。
- 表示するときは出典を書く：「出典：デジタル庁 アドレス・ベース・レジストリ（CC BY 4.0）を加工して作成」。
- 座標の測地系は EPSG:6668（JGD2011）と EPSG:4612（JGD2000）が混ざっている。GPS（WGS84）との差は数 m 以下なので、そのまま使っている。

## ライセンス

- `data/history/` の 1970 年の市町村・境界線は「地図地理Sandbox」（はにしな）、2000 年の町丁・字は e-Stat（政府標準利用規約）のデータを加工したもの。使うときはそれぞれの出典を表示する。

- プログラム（`tools/`・`c/`）：MIT（`LICENSE`）。
- データ（`raw/` の zip、`data/`）：デジタル庁 アドレス・ベース・レジストリ（CC BY 4.0）。`data/` はそれを加工したもの。
  使うときは「出典：デジタル庁 アドレス・ベース・レジストリを加工して作成」と表示する。
- `raw/` には元データの zip（約 16MB）だけを入れ、展開した CSV（約 190MB。1 個 156MB で GitHub の 100MB 制限を超える）は入れていない。
  そのため Git LFS は使っていない。

## 作り方

```bash
tools/fetch.sh                 # raw/ の zip を展開（約 190MB）。-f を付けると最新を取り直す
python3 tools/build.py         # data/ を作る（数秒）
cc -O2 -Wall -o c/rgeo_cli c/rgeo_cli.c -lm
python3 tools/verify.py 300    # 総当たりと答えが同じか確かめる
c/rgeo_cli data/rgeo_all.bin 35.690395 139.7661275
```

## できたもの（`data/`、元データ 2026-10-10 時点）

| ファイル | 中身 | 大きさ |
|---|---|---|
| `rgeo_all.bin` | 全国 209,330 点、1,826 市区町村 | 3.7MB |
| `pref/rgeo_XX.bin` | 都道府県ごと（XX＝都道府県コード）。例：東京 13 は 6,390 点 88KB、北海道 01 は 398KB、最大は京都 26 の 552KB | 18KB〜552KB |
| `towns.csv` | 使った点の一覧（lg_code, machiaza_id, 種別, 都道府県, 市区町村, 大字・町, 丁目, 小字, 緯度, 経度） | 17MB |
| `stats.json` | 件数・大きさ・元データの日付 | |

- 使った点：廃止されていない町字のうち、代表点があり名前が分かるもの（大字・町 91,599／丁目 91,190／小字 13,340 など）。
- 除いたもの：位置参照拡張にあるが町字マスターに名前が無い 128,311 点（`machiaza_id` が 0000xxx の古い番号など）。
  また、代表点の無い大字・町が約 14,000、丁目が約 2,600 ある（その町字の場所では、隣の町字が答えになる）。
- 「一番近い代表点」なので境界の近くでは隣の町字になることがある（区域の形のデータは使っていない）。
- ESP32 の容量の目安：フラッシュ 4MB の基板に全国版（3.7MB）は入らない。都道府県ごとのファイルを LittleFS に入れるか、全国版は SD カードに置く。

## RGEO 形式（v1、リトルエンディアン）

ヘッダー 68 バイト：

| 位置 | 型 | 中身 |
|---|---|---|
| 0 | char[4] | `RGEO` |
| 4 | u16 | 版（1） |
| 6 | u16 | ヘッダーの大きさ（68） |
| 8 | u32 | 点の数 |
| 12 | u32 | 市区町村の数 |
| 16 / 20 | i32 | 区画の南西の端の緯度・経度（度×1e6） |
| 24 | u32 | 区画の大きさ（度×1e6。250000＝0.25 度） |
| 28 / 30 | u16 | 区画の行数（南→北）・列数（西→東） |
| 32 | u32 | 区画の表の位置 |
| 36 | u32 | 点の表の位置 |
| 40 | u32 | 市区町村の表の位置 |
| 44 | u32 | 丁目の表の位置 |
| 48 | u32 | 文字列の表の位置 |
| 52 | u32 | 文字列の表の大きさ |
| 56 | u16 | 丁目の種類の数（0 番＝丁目なし） |
| 58 | u16 | 予備（0） |
| 60 | u32 | 元データの日付（YYYYMMDD） |
| 64 | u32 | CRC32（68 バイト目から最後まで） |

- 区画の表：u32 ×（行数×列数＋1）。区画 i（＝行×列数＋列）の点は、点の表の `[表[i], 表[i+1])`。
- 点の表：1 点 10 バイト。`u16 緯度の位置, u16 経度の位置`（区画の中を 0〜65535 で。約 0.4m 刻み）、`u16 市区町村の番号`、`u24 名前`（文字列の表の位置。大字・町＋小字）、`u8 丁目の番号`。
- 市区町村の表：1 件 12 バイト。`u32 全国地方公共団体コード, u32 都道府県名, u32 郡・市・区の名前`（文字列の表の位置）。
- 丁目の表：u32 × 丁目の種類の数（文字列の表の位置。「一丁目」「１丁目」など元データの書き方のまま 79 種）。
- 文字列の表：UTF-8、NUL 終わり。同じ文字列は 1 回だけ。0 番地は空文字列。

## 検索（`c/rgeo.h`）

- C / C++ のヘッダーだけ。読み出しは呼ぶ側の関数で行う（LittleFS・SD の File、フラッシュの区画、メモリ）ので、ファイル全体を RAM に載せなくてよい。malloc しない。
- 探し方：GPS の点がある区画から 1 周ずつ広げ、「次の周はもう今の答えより遠い」と分かったら終わる。距離は正距円筒近似。
- `c/rgeo_cli.c`：パソコンで試すためのもの。`-` を渡すと標準入力の「緯度 経度」を 1 行ずつ調べる（`tools/verify.py` が使う）。
- 確かめたこと：`tools/verify.py 300` で、ランダムな 300 点（海の上・範囲の外を含む）が総当たりの答えと全部一致（2026-10-12）。

## 1970 年の市町村（`data/history/`、2026-10-16）

今の町字の代表点が、1970 年 4 月 1 日（昭和 45 年）にどの市町村だったか。`tools/build_history.py` で作る。

- 元データ：**「地図地理Sandbox」市区町村境界時系列データ**（製作 はにしな、https://hanishina.net/maps/historydata.html ）。
  「目的を問わず利用・改変・再配布可能」、出典として「地図地理Sandbox」または「はにしな」の表記を推奨。
  `raw/history/polygon.fgb`（市区町村の形、START〜END の期間つき、17.6MB）と `raw/history/line.fgb`（境界線、15.4MB）を
  `curl -sfL -o raw/history/polygon.fgb https://hanishina.net/maps/tiles/polygon.fgb`（line.fgb も同様）で取る。
- 1970-04-01 にしたのは、北海道のデータがこの日から（ほかは 1947 年から）。湖・帰属未定地の形は除き、どの形にも入らない点は 3km 以内で一番近い形にした。
- 道具：pyogrio 0.13.0・shapely 2.2.0（`~/Documents/clock/.venv`）。

| ファイル | 中身 |
|---|---|
| `muni_1970.csv` | **対応表**：都道府県, 今の市区町村, 1970 年の市町村（都道府県＋郡＋名前）, 町字の数（3,696 組）。例：つくばみらい市 → 筑波郡伊奈村（52）・筑波郡谷和原村（69） |
| `town_1970.csv` | 町字ごと：lg_code, machiaza_id, 都道府県, 今の市区町村, 町字, 1970 年の郡・市, 1970 年の市町村 |
| `old1970.bin` | GeoLog 用。'OLD1', u32 点の数, u32 名前の数, u32 日付 / u16 × 点（rgeo_all.bin の点の順に名前の番号、0＝分からない）/ u32 × 名前（位置）/ 文字列「都道府県＋郡\t市町村」 |
| `bounds.bin` | GeoLog の拡大地図の境界線（今 2026-10-01 と 1970-04-01 の 2 組）。'BND1', u32 組 / 組ごと u32 日付, u32 線の数 / 線ごと u8 種類（1 都道府県界 2 支庁界 3 郡界 4 市町村界 5 区界 7 海 8 湖）, u8 陸湖海, u16 点の数, i32 南西北東, 点（i32 緯度・経度、度×1e6） |

- 1970 年の市町村が分からない町字は 17（関西国際空港・神戸ポートアイランド・中部国際空港など、1970 年には無かった埋立地）。

## 2000 年の町丁・字（`data/history/`、2026-10-16）

1970 年当時の町字を全国まとめて対応づけたデータは見つからなかった（住居表示の新旧対照表は市ごとで、多くは PDF）。
そこで、全国そろっている一番古い町丁・字の範囲のデータとして、**平成 12 年（2000 年）国勢調査の町丁・字等別境界データ**を使い、
今の町字の代表点がどの町丁・字に入るかを調べた（やり方は 1970 年の市町村と同じ。`tools/build_history.py`）。

- 元データ：**政府統計の総合窓口（e-Stat）**「平成12年国勢調査 町丁・字等別境界データ」（世界測地系緯度経度・Shape、都道府県ごと、全国 222,001 区域。https://www.e-stat.go.jp/ 、政府標準利用規約に従い加工して利用）。
  取り方は `tools/build_history.py` の先頭（`raw/h12/` に置く。約 300MB なのでリポジトリには入れない）。
- `town_2000.csv`：町字ごと（lg_code, machiaza_id, 都道府県, 今の市区町村, 町字, 2000 年の市区町村, 2000 年の町丁・字）。例：つくばみらい市中島 → 茨城県筑波郡伊奈町 大字中島。
  2000 年の町丁・字が分からないのは 6 町字。
- `old2000.bin`：GeoLog 用。'OLD2'（名前の番号が u32、ほかは old1970.bin と同じ）。rgeo_all.bin の点の順に、2000 年の町丁・字の名前（119,000 種）。
- GeoLog の OLD 表示は「1970 年の市町村」＋「2000 年の町丁・字」（例：茨城県筑波郡伊奈村大字中島）。時期が混ざるので、ボタンは「1970」ではなく「OLD」。
